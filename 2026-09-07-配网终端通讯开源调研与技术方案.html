配网终端通讯工具：开源调研与技术方案

日期：2026-09-07　状态：待确认　范围：IEC 60870-5-101/104 模拟主站、四遥测试、本地固定 IP 绑定
结论摘要
  • 没有单一开源项目同时完整覆盖「101+104 模拟主站 + 四遥测试 UI + 本地固定 IP 绑定」。
  • 协议层应以 lib60870 为基石（唯一同时覆盖 101/104，且原生支持本地 IP 绑定）。
  • 产品/交互层优先参考 Karl-Dai/IEC60870-5-104-Simulator 与 aixi224/IEC104_Tester，不要整仓 fork 其协议栈。
  • 推荐技术路线：Python 桌面壳（pywebview）+ 统一主站服务层 + lib60870（104 可用 c104，101 走 C 扩展/ctypes）。

2.2 明确降权/避免整仓复用

  • 纯自研 Python 协议栈作为长期底座（IEC104_Tester / py_iec104）：上手快，但链路层/窗口参数/异常路径易欠严谨，101 更难补齐。
  • FreyrSCADA 源码嵌入产品：本质是商业评估包，许可不适合作内部工具底座。
  • 整仓 fork Karl-Dai：104 产品化很好，但无 101；Rust 栈与现有 Python 工具链割裂；本地 IP 绑定需另核。
  • 仅用 c104：无 101，且需确认本地 bind API 是否完整暴露；不足时要回落 lib60870 C API。

3. 值得复用 vs 应避免

值得复用

  • CS104_Connection_setLocalAddress(localIp, localPort)：直接满足「绑定本地固定 IP」。
  • 协议核与 UI 解耦（Karl-Dai：core + event channel + desktop shell）。
  • 四遥测试工作流：点表管理、总召唤/对时、SBO 预置-执行、报文监视与解析、Excel/JSON 场景配置（IEC104_Tester）。
  • 多 CA / 点号分层展示（Karl-Dai Master）。
  • c104 的高层对象模型：Connection → Station → Point → 回调。

应避免

  • UI 与协议状态机揉在一个脚本文件里，无法单测。
  • 101/104 各写一套互不兼容的点表模型。
  • 默认 0.0.0.0 / 系统选源地址，却声称支持多网卡现场。
  • GPL 依赖进入闭源商业分发而不评估合规（若仅内部工具通常可接受，但仍需明确）。
  • 过早做从站模拟、文件传输、TLS/62351，挤压 MVP。

4. 技术方案（待确认）

方案对比

方案技术栈优点风险推荐
A. Python 桌面 + lib60870 Python 3.11+、pywebview、c104（104）、lib60870/ctypes 或薄 C 扩展（101）、pyserial、JSON/Excel 与现有规约工具习惯一致；101/104 可统一；本地 IP 可落地；交付快 需处理 GPL；Windows 下原生扩展打包；101 串口现场差异大 推荐
B. Rust 协议核 + Tauri 对齐 Karl-Dai：Rust+Tokio+Tauri+Vue 性能与产品化强；MIT 友好 无现成 101；学习/工期高；与现有 Python 工具不统一 备选（长期产品化）
C. 纯 Python 自研协议 对齐 IEC104_Tester 零原生依赖、MIT、改得快 101 成本高；协议正确性/稳定性风险大；本地 bind 要自己做 不推荐作底座
推荐方案 A 细节
  • 壳：pywebview 桌面应用；弹窗统一走应用内悬浮窗（与 MaintainTool 同类约定一致）。
  • 应用服务：MasterService 抽象；Iec104Master / Iec101Master 适配器；统一点表、会话、命令、报文事件总线。
  • 104：优先 c104；若缺本地 IP 绑定 API，则对 lib60870 做薄封装补齐 setLocalAddress。
  • 101：lib60870 CS101_Master + 串口参数（平衡/非平衡、链路地址、波特率等）。
  • 数据：JSON 工程文件 + 可选 Excel 点表导入；会话日志可导出。

5. MVP 范围

纳入 MVP暂不纳入
  • 104 模拟主站：连接、STARTDT、总召唤、时钟同步
  • 四遥：遥信/遥测监视；单/双点遥控（含 SBO）；浮点/归一化设点（遥调）
  • 本地网卡/IP 选择并绑定源地址
  • 点表增删改、JSON 保存、基础报文监视（收发十六进制+简要解析）
  • 101 模拟主站最小集：串口打开、非平衡主站轮询或平衡模式二选一（先定一种）、总召唤与基础四遥
  • 从站模拟器
  • 文件传输、参数下载全套、电度量复杂统计
  • TLS / IEC 62351
  • 104 冗余组、多主并发压力测试
  • 完整一致性测试套件、自动报告

6. 开发顺序

  1. 骨架：工程结构、pywebview 壳、事件总线、工程/点表模型。
  2. 104 主站连通：连接参数 + 本地 IP 绑定 + STARTDT + 总召唤 + 点值刷新。
  3. 104 四遥命令：遥控 SBO、设点、失败/超时反馈、报文监视。
  4. 101 主站最小通路：串口 + 链路模式 + 总召唤 + 与 104 共用点表/UI。
  5. 场景化：Excel 导入、常用配网点表模板、会话日志导出。
  6. 硬化：异常重连、参数校验、打包（PyInstaller）、现场网卡绑定回归。

7. 已确认决策（2026-09-07）

  • 产品形态：Windows 桌面，方案 A（Python + pywebview）。
  • 许可：接受 GPL（内部工具，可依赖 lib60870 / c104）。
  • 101：优先平衡模式；串口细节后续再定。本阶段不实现 101。
  • 交付节奏：先交付 104 MVP，101 后续迭代。
  • 本地绑定范围：固定本地 IP + 可指定本地端口 + 多网卡列表选择 + 连接失败明确提示。

8. 关键改动点（待确认后编码）

改什么

  • 新建工程骨架：app/（pywebview 入口）、ui/（前端）、core/（点表/事件/工程）、protocol/iec104/（主站适配）、net/（网卡枚举与本地绑定）。
  • 104 模拟主站：连接、STARTDT、总召唤、时钟同步；遥信/遥测监视；遥控 SBO；设点（遥调）。
  • 本地绑定：枚举本机网卡 IPv4；选择本地 IP；可选本地端口（空=系统分配）；连接前 setLocalAddress；失败分类提示（网卡不存在/绑定失败/对端拒绝/超时）。
  • UI：连接配置、点表、四遥操作、报文监视；弹窗走应用内悬浮窗，不用原生 alert/confirm。
  • 依赖：c104（优先）+ 必要时 lib60870 薄封装补本地 bind；GPL 声明文件。

不改 / 不做（本阶段）

  • 不做 101、从站模拟、文件传输、TLS、冗余组。
  • 不引入 Tauri/Rust；不自研纯 Python 104 协议栈作底座。

验证方式

  • 本机多网卡：选指定 IP 连接从站，用抓包/日志确认源地址正确。
  • 指定/不指定本地端口均可连通；错误 IP/端口有明确中文提示。
  • 对测试从站完成总召唤、遥控 SBO、设点闭环。

残留风险

  • c104 若未暴露本地 bind，需补 ctypes/扩展，略增工期。
  • Windows 下网卡枚举与权限、防火墙可能导致绑定成功但不通，需提示排查。
  • PyInstaller 打包含原生库时需单独验证。
